先把“记忆”拆成两个问题

本课唯一目标：你能判断一条信息应该放进 Checkpointer，还是放进 Store。

两个问题

第一问是“这次对话接着上一步继续吗？”这是 thread_id 和 Checkpointer 解决的 thread-scoped 短期状态。

第二问是“换一个对话后，还应该保留这条信息吗？”这是 Store 解决的 cross-thread 长期数据；namespace 决定哪些用户、Agent 或组织能看到它。

同一 thread
    └─ Checkpointer ──► 消息、当前状态、临时工作

新 thread / 新会话
    └─ Store + namespace ──► 偏好、项目知识、研究记忆
先记住这个边界：模型说“我记住了”只是回答。真正的写入证据应该来自 Store 中的 item，或 tracing 中成功的文件工具调用。

先回忆，再看答案

  1. 同一个用户换了 thread_id，仍想保留“中文注释”的偏好，你会增加什么组件？
  2. 两个用户都使用 /preferences.md，如何避免读到彼此的内容？
  3. 如果一个组织策略不应被 Agent 改写，应该只依靠提示词吗？
参考答案

使用跨 thread 的 Store；用包含用户身份的 namespace 隔离同名 key；不能只依靠提示词，还需要只读路由、权限规则或由应用代码写入并审计。

本课完成标准

  • 能说出 Checkpointer 和 Store 各自的生命周期。
  • 能解释为什么 thread_id 不能替代 namespace。
  • 能运行 实验 1 和 实验 2，并把观察写入记录。
