把人工决定交给工作流

本课只练习批准原请求，并预测工具执行后留下的证据。

先认识四种选择

决定含义
approve按原参数执行工具
edit修改参数后执行工具
reject跳过此次调用，把拒绝反馈交给模型
respond人直接提供工具结果，适合 ask_user 这类工具

选择受 allowed_decisions 限制。上一课的工具只允许 approve 和 reject；要练 edit，后续会先调整配置。respond 的内容被作为成功工具结果，不能拿它来表达拒绝写入。依据：LangChain 官方 HITL。

本轮只补一个字段

继续上一课的请求：将 language 改为 English。假设你检查后同意原样执行，补全下面的 type。

# 接在已有 agent、config 和暂停结果之后，不是独立脚本
from langgraph.types import Command

decision = {"type": "_____"}
result = agent.invoke(
    Command(resume={"decisions": [decision]}),
    config=config,  # 使用发起时的同一线程配置
    version="v2",
)

Command(resume=...) 把决定交回暂停的工作流。完整恢复机制留到第三节，这次只关注决定的含义。恢复机制来源

预测可观察结果

模拟工具体如下；本轮假设只执行这一次调用，没有重试或新增调用：

def update_preference(key, value):
    executed_calls.append({"key": key, "value": value})
    return "updated"

执行前 executed_calls == []。批准并成功执行后，里面应出现什么？这份列表只证明模拟工具体被执行，不代表已经写入真实 Store。

先作答，再查看对照

type 填 approve。列表应为 [{"key": "language", "value": "English"}]。批准沿用原参数；实际执行记录比模型说“完成”更能说明工具运行了。若要证明真实持久化，还应检查目标 Store。
