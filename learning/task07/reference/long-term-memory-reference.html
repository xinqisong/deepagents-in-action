Task 07 · Reference

长期记忆与 CompositeBackend

用作用域、存储和路径三件事定位问题。

最小词汇表

概念一句话典型边界
thread一次可持续恢复的对话执行上下文由 thread_id 标识
Checkpointer保存 thread 内的 Agent state换 thread 默认不共享
Store保存可跨 thread 读取的数据由 namespace 隔离
namespaceStore 中的逻辑隔离边界常包含 user_id / assistant_id / org_id
CompositeBackend按虚拟路径把文件操作分发给不同 Backend/memories/ 可走 StoreBackend
memory=指定启动时要加载的已有记忆文件不等于自动保证写入

路径与 Store key

Agent 可见路径：/memories/preferences.md
路由前缀：      /memories/
Store 中的 key： /preferences.md
namespace：      (user_id, "memories")
常见误判：同一个 key 只在同一个 namespace 内代表同一份数据；同名不代表共享。写入前要检查旧 item，避免第一次初始化代码覆盖已有偏好。

作用域选择

信息推荐边界安全取舍
用户偏好(user_id, "memories")用户可请求更新，仍应检查写入结果
Agent 知识(assistant_id, "memories")共享给多个用户，需防止任意用户注入
组织策略(org_id, "policies")应用代码写入，Agent 通常只读

排障顺序

  1. 我观察的是哪个来源：Store item、Agent state、run 还是 trace？
  2. 当前使用的是哪个 thread_id 和 namespace？
  3. Agent 可见路径与 Store key 是否多了一层路由前缀？
  4. 是“模型回复成功”，还是“持久化写入成功”？
  5. 是本地 InMemoryStore 重启丢失，还是持久化 Store 真正读不到？
