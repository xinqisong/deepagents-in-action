Deep Agents · Task 06

AsyncSubAgent 速查页

异步子 Agent 的核心不是“同时调用几个函数”，而是把长任务变成一个可以启动、查询、更新和取消的后台生命周期。

一句话判断：短而且需要立即拿结果，用同步 task；可能持续数分钟、允许用户继续对话并需要中途控制，用 AsyncSubAgent。

1. 同步与异步

维度同步 SubAgent异步 SubAgent
入口taskstart_async_task
返回等待最终结果立即返回完整 task ID
主 Agent调用期间等待可以继续服务用户
中途控制不支持check / update / cancel / list
状态一次调用一次结果独立 thread 持续累积历史

2. 配置契约

from deepagents import AsyncSubAgent, create_deep_agent

subagents = [
    AsyncSubAgent(
        name="researcher",
        description="需要多次搜索和综合资料的长程研究",
        graph_id="researcher",
        # 不写 url：同部署 ASGI
        # url="https://example.com"：远程 HTTP
    )
]

agent = create_deep_agent(model=model, subagents=subagents)
  • name：主 Agent 选择任务时使用的唯一名称。
  • description：路由线索，要写“什么时候使用”和“能完成什么”。
  • graph_id：Agent Protocol 服务上的 graph 名称，必须和 langgraph.json 一致。
  • url：省略走同部署 ASGI；填写走远程 HTTP。
  • headers：自托管 HTTP 服务需要自定义鉴权时使用。

3. 五个控制工具

工具什么时候用关键动作
start_async_task用户要求开始长任务记录完整 task ID，立即交还控制权
check_async_task用户询问进度或结果读取实时状态，完成后取最终输出
update_async_task用户追加约束在原 thread 上追加指令，不重开任务
cancel_async_task用户要求停止工具先确认 cancelled；再区分服务端 run 与 tracing 状态
list_async_tasks需要任务总览查看所有任务的实时状态

4. 生命周期

用户：开始长任务
  ↓
Supervisor → start_async_task
  ↓
立即得到 task_id；后台 researcher 继续运行
  ↓
用户可继续聊天
  ├─ 问进度 → check_async_task
  ├─ 加约束 → update_async_task
  ├─ 停止    → cancel_async_task
  └─ 看总览  → list_async_tasks
  ↓
控制工具常见终态：success / error / cancelled
被打断的具体 run 或 tracing：可能是 interrupted
状态来源要分层：cancel_async_task 的确认、服务端某个 run.status 和 LangSmith tracing 不是同一个字段。当前 deepagents==0.7.19 中，取消后再次 check_async_task 会读取服务端 run 的原始状态，因此可能出现“工具返回 cancelled，随后 check/tracing 显示 interrupted”。update_async_task 也会用 multitask_strategy="interrupt" 中断旧 run。
不要把状态当质量：success 只说明后台 run 正常结束。研究结论是否有依据，仍需来源核验、结构化校验或人工审核。

5. 部署与排障

  • langgraph.json 同时注册 supervisor 和 researcher；graph_id 对不上时会找不到 Agent。
  • 本地起步：langgraph dev --n-jobs-per-worker 4。每个活跃 run 占一个 worker 槽位。
  • 同步入口与本地 ASGI 要分清：当前 deepagents 类型说明要求省略 url 的 ASGI 传输通过异步父入口调用，例如 ainvoke。
  • 状态回答必须先 check/list；对话历史中的旧状态可能已经过时。
  • 保留完整 task ID、thread ID 和 run ID，便于在 LangSmith 中把 supervisor 与子 Agent trace 对上。
  • 取消后要记录状态来源：工具结果、check/list 结果、服务端 run 和 LangSmith tracing 可能不同。
