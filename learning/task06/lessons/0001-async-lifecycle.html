Task 06 · Lesson 01 · 约 10 分钟

先把“异步”想成一项后台工作

本课的唯一目标：你能解释为什么同步 task 不适合长程、可交互任务，并能说出异步任务的四个后续动作。

从 task05 接过来的问题

task05 的主 Agent 调用同步子 Agent 后，会等待子 Agent 完成，再拿到结果。如果研究需要几分钟，用户只能等待；如果用户中途想补充“换数据源”或“只关注某个主题”，同步调用没有一个自然的控制入口。

新的心智模型

启动不是完成

Supervisor ── start_async_task ──► 后台 thread / run
     │                              │
     └── 立刻继续和用户对话          ├─ check：现在怎样？
                                    ├─ update：加一个约束
                                    ├─ cancel：停止
                                    └─ list：查看总览
最重要的区分：异步子 Agent 是“可管理的后台任务”，不是“把所有同步调用包进 asyncio.gather”。前者有 task ID、独立 thread、状态查询和中途控制；后者只是程序内部的并发写法。

先做一次回忆，再打开答案

  1. 如果子任务预计 2 秒完成，你会选同步还是异步？为什么？
  2. 如果用户问“刚才那个后台任务现在完成了吗？”，主 Agent 应该先做什么？
  3. 为什么不能只从旧的 ToolMessage 里读取任务状态？
参考答案

2 秒且需要立即拿结果时选同步；询问进度时先调用 check_async_task 或 list_async_tasks；任务元数据应该在独立的 async_tasks state channel 中保存，因为消息历史可能被压缩，旧消息里的状态也可能过时。

本课完成标准

  • 不用看资料，能说出 start、check、update、cancel、list 的顺序和用途。
  • 能指出“success ≠ 结论正确”。
  • 能说明异步子 Agent 为什么需要 Agent Protocol 服务，而不只是一个 Python 协程。
