Deep Agents · Task 07

Skills 速查页

Skill 是可复用的领域工作流包：它把触发条件、操作步骤、参考资料和可选代码放在一个目录里，并按需加载。

一句话心智模型：Tool 告诉 Agent “能做一个什么原子动作”；Skill 告诉 Agent “遇到某类任务时，应该按什么流程组合动作”。

1. 最小目录

skills/
└── report-review/
    ├── SKILL.md          # 必需：frontmatter + 指令
    ├── scripts/           # 可选：可执行代码
    ├── references/        # 可选：按需阅读的详细资料
    └── assets/            # 可选：模板、schema、静态资源

2. SKILL.md 契约

---
name: report-review
description: 审查研究报告的来源、证据和结论。用户要求核验报告质量或引用时使用。
---

# report-review

1. 找出每个关键结论。
2. 对照来源和证据。
3. 输出问题、证据和改进建议。
  • name 必填：小写字母、数字和连字符，且与父目录名一致。
  • description 必填：同时写“做什么”和“什么时候使用”；它是启动时的主要路由线索。
  • 正文写 Agent 的执行剧本；过长内容拆到 references/。

3. 三层渐进式披露

层级内容何时进入上下文
1 Metadataname、description、路径Agent 启动时，所有已配置 Skill 都发现
2 Instructions完整 SKILL.md 正文任务匹配 Skill 后，Agent 读取正文
3 Resourcesscripts/、references/、assets/正文引用且任务确实需要时，按需读取

4. 三种能力注入方式

机制适合放什么典型问题
Tool搜索、读写文件、调用 API 等原子操作Agent 要执行哪个动作？
Memory每次对话都相关的规范、偏好、项目背景所有任务都需要知道什么？
Skill特定任务才需要的多步骤流程、知识和资源遇到哪类任务时要按什么剧本做？

5. Backend 与优先级

  • FilesystemBackend：本地目录；实验时使用 virtual_mode=True。
  • StateBackend：文件放在当前 Agent state；调用时通过 files 注入，并用 create_file_data() 格式化。
  • StoreBackend：通过 Store 跨 thread 持久化；生产场景要设计 namespace 隔离。
  • skills=["/skills/"] 指向 Skill 父目录，不是某个单独的 SKILL.md。
  • 同名 Skill 多源并存时，后列的 source 覆盖前列的 source（last wins）。
安全边界：能读取 Skill 文件，不等于能执行其中脚本；执行还需要合适的沙箱或解释器，以及明确的权限策略。共享 Skill 库通常应只读，个人 Skill 才考虑可写或审批写入。
